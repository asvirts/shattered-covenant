# Story Progress Is a Set of Story Beats; the World Phase Is Derived

All story progress lives in one append-only set of typed **Story Beats** on `WorldMemory`. The **World Phase** is computed from beats and never stored, and hero recruitment and the Heart-Shard's fusion are beats too, read through helpers rather than fields on `Hero`. Only **Scenes** (async TypeScript functions) add beats, and Zones change across the story through beat-gated layers and triggers declared in Zone data. One record means the Act, the party and each Zone's state can't disagree, a misspelled beat fails to compile, and the save format later only has to store a set of strings.

**Considered options:** separate typed fields per kind of progress, with the Act stored and advanced by hand (rejected because each new kind of progress needs a new field and the Act can drift out of step), and untyped free-form flags (rejected because typos fail silently and nothing lists what exists). We also considered keeping `recruited`/`presentation` on heroes, mirrored from beats (rejected because two copies get out of sync). For scenes, data step lists run by an interpreter were rejected because branching is clumsy and every new step needs interpreter work. That option would have allowed saving mid-scene, which this decision gives up.
